Module 1: The Foundations & The CIA Triad

At the heart of all information security principles lies the CIA Triad: Confidentiality, Integrity, and Availability. Every control, security tool, or policy aims to protect one or more of these pillars.

The Three Pillars

  • Confidentiality: Ensuring that data is accessible only to authorized personnel. (e.g., Encryption, Access Control Lists).
  • Integrity: Guaranteeing that information is accurate, trustworthy, and has not been altered by unauthorized parties. (e.g., Hashing, Digital Signatures).
  • Availability: Ensuring that systems, networks, and data are accessible to authorized users when needed. (e.g., Redundancy, DDoS Protection, Backups).

Key Takeaway

Security is always a trade-off with usability. The goal is not to create an impenetrable system (which would be unusable), but to manage risk effectively while enabling operational capacity.

Module 2: Networking Fundamentals & Protocols

To defend a network, you must understand how data travels across interconnected systems. The OSI Model defines seven layers of abstraction for network communication.

OSI Model Overview

Layer Name Primary Protocols / Devices Security Mechanisms
7 Application HTTP, HTTPS, FTP, DNS, SSH Web Application Firewalls (WAF), Input Sanitization
4 Transport TCP, UDP Port Filtering, TLS Handshakes
3 Network IP, ICMP, IPSec Network Firewalls, Routers, Subnetting
2 Data Link Ethernet, ARP, Switches MAC Filtering, Port Security, 802.1X

Common Attack Vectors in Networking

  • Man-in-the-Middle (MitM): An attacker intercepts communication between two parties (e.g., via ARP Spoofing).
  • DNS Spoofing: Poisoning DNS caches to redirect legitimate traffic to malicious IP addresses.

Module 3: Web Application Security & OWASP Top 10

Web applications are exposed to the public internet and represent a massive attack surface. The Open Web Application Security Project (OWASP) highlights the most critical risks.

1. SQL Injection (SQLi)

Occurs when untrusted user input is directly concatenated into a database query.

Vulnerable Code Example (Node.js/SQL)

// UNSAFE: Direct string concatenation allows input like " ' OR '1'='1 "
const query = `SELECT * FROM users WHERE username = '${req.body.username}' AND password = '${req.body.password}'`;
db.query(query);

Secure Remediation (Parameterized Query)

// SAFE: Uses placeholders to separate code from execution data
const query = `SELECT * FROM users WHERE username = ? AND password = ?`;
db.query(query, [req.body.username, req.body.password]);

2. Cross-Site Scripting (XSS)

Occurs when an attacker injects malicious JavaScript into data sent to other web users.

  • Stored XSS: The script is permanently stored in a database (e.g., in a comment section).
  • Reflected XSS: The script is reflected off the web server in an error message or search result.

Module 4: Cryptography & Data Protection

Cryptography provides mechanisms to protect confidentiality and integrity using mathematical algorithms.

Types of Cryptography

  • Symmetric Encryption: Uses a single secret key for both encryption and decryption. Fast and efficient for large data sets. Example: AES-256.
  • Asymmetric Encryption: Uses a key pair: a public key for encryption and a private key for decryption. Example: RSA, ECC.
  • Cryptographic Hashing: A one-way deterministic function that maps input to a fixed-length string. Used to verify integrity. Example: SHA-256.

Hashing vs Encryption

// Hashing (One-Way)
Input:  "Pass123!" --(SHA-256)--> Output: "e80b5017098950fc58aad83c8c14978e..."
Note: You CANNOT reverse the output back to "Pass123!".

// Encryption (Two-Way)
Plaintext: "Secret Message" --(Encrypt with Key)--> Ciphertext: "a8f9d3k2"
Ciphertext: "a8f9d3k2"       --(Decrypt with Key)--> Plaintext: "Secret Message"

Module 5: Identity & Access Management (IAM)

IAM ensures the right entities have access to the right resources at the right time for the right reasons.

Core Frameworks

  • AAA Framework: Authentication (Who are you?), Authorization (What are you allowed to do?), Accounting (What did you do?).
  • Multi-Factor Authentication (MFA): Requiring two or more proof factors:
    • Something you know: Password, PIN
    • Something you have: Security token, Authenticator App
    • Something you are: Biometrics (Fingerprint, Facial Recognition)
  • Principle of Least Privilege (PoLP): Users and systems should only be granted the minimum permissions strictly necessary to complete their operational tasks.

Module 6: Endpoint Security & Malware Analysis

Endpoints (workstations, servers, mobile devices) are primary targets for malicious actors seeking entry into enterprise networks.

Common Malware Categories

  • Ransomware: Encrypts victim files and demands payment for the decryption key.
  • Trojan: Disguises itself as legitimate software to trick users into executing it.
  • Keylogger: Monitored software or hardware that records keystrokes to steal credentials.
  • Worm: Self-replicating malware that spreads across networks without human interaction.

Hardening Controls

  • Implement Endpoint Detection and Response (EDR) solutions.
  • Enforce full-disk encryption (e.g., BitLocker, FileVault).
  • Disable unnecessary services and ports.
  • Maintain automated patch management pipelines.

Module 7: Incident Response Lifecycle

When a breach occurs, structured incident response limits damage and reduces recovery time and cost.

NIST Incident Response Steps

  1. Preparation: Establishing policies, communication plans, and securing tools before an incident occurs.
  2. Detection & Analysis: Monitoring alerts, identifying anomalies, and verifying whether a breach has occurred.
  3. Containment, Eradication, & Recovery:
    • Containment: Isolating affected systems to prevent spread.
    • Eradication: Removing threat artifacts (malware, unauthorized user accounts).
    • Recovery: Restoring systems from trusted backups back into production.
  4. Post-Incident Activity: Documenting lessons learned to improve future security posture.
